# CIRCLO — Build your circle anywhere.

A community & relocation app for students and working professionals moving to a new city:
accommodation, flatmates, people from your college/hometown, local community, and events.

## Tech stack

- React 18 + TypeScript
- Vite
- Tailwind CSS
- React Router v6
- lucide-react icons

## Getting started

This project was generated by hand (no `npm install` was run in the build sandbox — it has
no network access), so the first run needs one install step:

```bash
cd circlo
npm install
npm run dev
```

Then open the printed local URL (usually `http://localhost:5173`). On desktop the app renders
inside a phone-style frame; on a mobile device or a narrow browser window it fills the screen.

Build for production:

```bash
npm run build
npm run preview
```

## Flow

```
/                → Welcome (phone login + Google mock)
/profile-setup   → Step 1 of 3 — name, occupation, hometown, college
/moving          → Step 2 of 3 — destination city, move-in date, reason
/requirements    → Step 3 of 3 — group size, budget, property type, bachelor-friendly
/home, /places   → Main accommodation feed (search, filters, favorites)
/listing/:id     → Listing details (gallery, amenities, call/WhatsApp actions)
/people          → People discovery (search + college/hometown/state filters)
/community       → Local forum (Questions / Recommendations / Events, ask+upvote+bookmark)
/profile         → Profile, My Move group, saved places, account settings
```

All onboarding and discovery routes are gated behind a mock `isAuthenticated` flag in
`AppContext` — logging in (via OTP `1234` or "Continue with Google") unlocks them, and
"Log Out" on the Profile screen returns to Welcome.

## Mock data → real backend

Everything currently lives in `src/data/*.ts` and in-memory state inside `AppContext.tsx`.
To connect a real backend (e.g. Supabase or Firebase):

1. Add the SDK (`npm install @supabase/supabase-js` or `firebase`) and an `src/lib/client.ts`
   with your project keys (use environment variables, not hardcoded keys).
2. Replace the static imports in `src/data/*.ts` with fetch functions (e.g.
   `getProperties()`, `getUsers()`, `getPosts()`) that call your database.
3. In `AppContext.tsx`, swap the `useState` initializers for data fetched on mount
   (`useEffect` + your fetch functions), and replace `login()` with a real phone/OTP or
   OAuth call.
4. Persist `profile`, `favorites`, and `connections` writes with real mutations
   (insert/update calls) instead of local `setState`.

The component layer (pages/components) doesn't need to change — it already reads
everything through `useApp()`, so swapping the data source is isolated to `AppContext`
and `src/data`.

## Notes

- Property and avatar images are pulled from Unsplash / DiceBear at runtime, so an internet
  connection is needed to see images when running the app.
- OTP verification is mocked — any 4-digit code works after you tap "Send OTP"; the modal
  hints at `1234` for convenience.
